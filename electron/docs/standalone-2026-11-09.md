# Electron 独立迁移与验证 — 2026-11-09

## 独立边界与唯一维护源

- `main.js` 只加载本项目 `webapp/index.html`。开发和生产使用相同相对目录，生产页面位于 `resources/app.asar/webapp/`。
- `package.json` 打包白名单只包含主进程、preload、正式 renderer 和 webapp。图标位于本项目，不再读取相邻 Android 项目；不再使用外部 `extraResources`。
- 业务页面、数据层、工具、商品目录、拼音库、样式、品牌图标和 Three.js 全部位于 Electron 目录内。保留第三方库说明和许可证。
- 外壳模板和原始外壳样式只维护 `renderer/src/`；`renderer/generated/` 由构建脚本生成并加入忽略规则。构建不读取 `docs/`。
- `renderer/desktop.js` 是唯一路由和窗口控制器，`renderer/warehouse-scene.js` 是唯一场景源。移除 Electron 内复制的旧首页、旧路由、沙盘控制器、旧沙盘页面/场景、重复 Three.js、原型示例控制器及失效的预览/诊断脚本。历史规格和截图保留作设计记录。
- 删除已确认未引用的旧品牌尺寸和 Logo 副本、旧沙盘和页面过渡样式。既有业务表单继续沿用原有视觉结构。
- `tests/standalone.test.cjs` 只复制 Electron 运行源和构建脚本到独立临时目录，重新生成外壳并启动成功；该目录没有 Android 或 docs。

## 性能处理与实测

测量使用真实 Electron 31.7.7、1440×900 内容区、独立临时 profile；每段渲染采样 800 ms。优化后检测到 RTX 3060 Laptop GPU / ANGLE D3D11。帧数是实际 renderer 帧计数，并非只检查暂停标志。

| 项目 | 修改前 | 修改后 |
| --- | ---: | ---: |
| 首页动画 / 800 ms | 23 帧 | 22 帧 |
| 打开业务模块 / 800 ms | 23 帧 | 0 帧 |
| 隐藏原生窗口 / 800 ms | 24 帧 | 0 帧 |
| 手动暂停动画 / 800 ms | 0 帧 | 0 帧 |
| 无数据变化的刷新均值 | 0.61 ms | 约 0.02 ms |
| 5000 单据，无变化重复刷新均值 | 10.61 ms | 低于本次计时显示精度（记录 0 ms） |
| 5000 单据统计页面首次渲染 | 9.3 ms | 12.7 ms |

这是单机有限次数采样，首次导入/统计时间存在波动；没有把统计首次渲染标记为提速。当前证据支持消除后台绘制和重复刷新工作，尚不足以认定统计算法本身为瓶颈，因此保留现有统计口径和算法。

具体处理：

1. 打开任意业务窗口、隐藏/最小化原生窗口和页面隐藏时停止 3D 绘制；返回首页复用同一实例。保持 30 FPS、1.25 像素比上限，并尊重手动暂停和系统减少动态效果。
2. 处理原生可见状态事件的时序，避免隐藏状态误判；页面加载完成后显示窗口，避免懒加载场景与 ready-to-show 互相等待。
3. Store 成功提交后递增 revision；经营指标、月度分组和分类数按 revision/日期更新。无变化的 refresh 跳过重复排序、分组和 DOM 重建；失败写入不发布成功状态。
4. 合并指标测量的 animationFrame，标记坐标批量读尺寸后再写样式，复用逐帧向量，避免重复加载场景脚本。
5. 场景销毁释放指针/可见性/媒体查询监听、ResizeObserver、RAF、几何体、材质、纹理、阴影和 WebGL 上下文；销毁/重启及异步加载期间的状态变化均受保护。
6. 取消单据列表离开后的搜索防抖，移除设置页无必要的每秒状态轮询。反复切换模块仍仅有一个 renderer，几何体/纹理计数稳定；销毁后两者均为 0。
7. 同一 profile 采用单实例写入，防止多个缓存写入者相互覆盖。原生菜单导航复用桌面未保存确认逻辑。

原始测量：`.shots/standalone/performance-before.json` 和 `performance-after.json`。

## 销售趋势

趋势列宽限定为 44–76 px，列间距 10 px，柱宽为列宽的 70% 且不超过 56 px。日期较少时不会因整行拉伸而产生过大柱间空白；日期较多时横向滚动。柱体和日期占用独立区域，金额高度保持比例。移除原先不存在的“点击图例”提示。

检查包含空数据、单日、30 个销售日、比例高度和标签边界，窗口覆盖 1440×900 与 1024×680。截图见 `.shots/standalone/trend-1440.png`、`trend-1024.png`。

## 功能和数据

- 保持应用名、appId、userData 默认位置、业务 localStorage 键及 version-1 JSON 备份格式。
- 兼容测试先在临时旧路径写入既有数据并退出，再通过新入口启动独立进程。原有单据、客户、商品、图片路径、一客一价、序号和桌面偏好保持；JSON 恢复和重载后再次核验。
- 测试期间检测到商品目录及初始化逻辑同步更新，予以保留。目录升级允许补充内置商品，同时逐字段核验已有用户商品及其已设价格不被覆盖。
- 开单、复制新增、数量/价格校验、保存失败回退与重试、单据日期和序号、客户/商品编辑、搜索、账单、备份恢复、图片读取均已回归。
- 原生文件测试经过真实 preload 和 IPC，并实际读写临时文件；对话框由测试替代。覆盖保存成功、取消、不存在目录导致的错误、导入后回调释放、图片复制与 `sdimg` 读取。
- 打印 IPC 测试检查系统打印派发和错误提示，替代系统打印回调。另通过真实 Chromium printToPDF 生成一页单据，提取确认客户、500ml 规格、1234.56 金额，且没有工作台界面或“已保存”提示。未向物理打印机出纸。
- 全部测试只用临时 profile，未读取或覆盖日常数据。

## 安装包验证边界

安装包为 `dist/送货单统计 Setup 1.0.0.exe`。核验脚本将安装包完整解压到临时目录，比较其中 `app.asar` 和 EXE 与构建目录内容，再使用真实 EXE、全新 profile 执行 10 项启动自检。

当前自动化会话直接执行仓库 `dist/win-unpacked` 下的 EXE 提前退出，退出码为 2147483651（0x80000003）。同一安装包完整解压到独立临时目录后，真实 EXE 启动和 10 项自检通过；项目 Electron 运行时执行 app.asar 也通过。两种结果分别记录，未把仓库构建目录直接启动标记为通过，也未为此修改正式启动参数或关闭正式沙箱。

安装包 SHA-256、字节数、文件清单和各类启动结果见 `.shots/standalone/package-verification.json`。尚未执行会修改系统安装状态的安装/卸载流程；安装包未配置商业签名。macOS/Linux 构建未验证。

## 保留边界

JSON 备份仍不包含图片二进制；跨电脑需复制图片目录。多键 localStorage 的异常回退不等于断电事务原子性。此轮没有切换存储引擎、重定义金额算法或替换 Android 构建产物。
