# 2.0.0 扫码送货单

## 操作流程

1. 软件保持在前台。在首页或普通单据查看页面，扫描数字商品条码，以 Enter 结束。第一次扫描自动打开扫码送货单；开单页的专用扫码框也支持手输、粘贴和字母条码。
2. 商品条码精确匹配本地资料，数量默认 1。重复扫描按相同商品、规格、单位、单价合并数量。每次完整扫码都是一次记录，不按相同条码去重。
3. 选择本单客户，或者明确选择散客。客户不会从上一单继承。存在客户价差异时会确认，手动改价保留；切换客户后没有默认售价的行必须确认单价。
4. 连续 60 秒没有扫码或修改单据后，显示覆盖整个软件的保存确认，背景不可操作。也可点击“提前结束本单”。移动鼠标不重置计时；编辑数量、选择客户、处理异常时暂停，完成后重新计时。休眠或切后台不会丢弃草稿，回到软件后按实际时间检查超时。
5. 确认期间的新扫码按顺序暂存，扫码结束回车不会触发保存。“补入本单”明确归入当前单；“保存本单，再开下一单”先提交当前单，再将暂存内容带到没有客户的新草稿。
6. 保存成功才计入原有单据、统计和账单。保存失败可重试；重启恢复同一个草稿。已经提交但尚未清理的草稿通过固定单据 ID 检查，避免重复生成。

## 扫码枪设置

- 默认接入：USB HID 键盘模式，数字条码连续输入，Enter 后缀。首页使用完整的 6–32 位快速数字输入；字符间隔超过 100ms 视为新的输入片段。普通输入框内暂停自动识别，避免干扰手工输入。字母条码请使用专用扫码框或前缀模式。
- 推荐接入：如果设备支持，设置 F9 前缀和 Enter 后缀，再在软件“扫码设置”切到 F9 模式。已识别的扫码字符不会输入价格、数量等字段。
- 软件不会读取其他程序的输入，不支持在软件未获得键盘焦点时从其他软件抢接扫码。先用记事本确认设备输出，再用少量真实商品验收。
- 扫码枪读码成功不代表商品已记账。软件提供声音、提示以及本单数量、金额反馈；未登记条码、缺价、重复条码、下架商品进入待处理区。

## 数据保护与兼容

- 扫码草稿使用独立键 `sd_v1_scan_session_v2`，接入原有桌面文件存储，每次扫码和有效编辑后写入。该键不进入正式销售报表；本机自动数据镜像包含该键。
- 草稿不是正式单据，现有便携 ZIP/JSON 业务导出不包含未完成扫码草稿。换机前请先完成当前扫码单。恢复整份业务备份或清空业务数据时，会清理旧扫码草稿，避免串入另一套资料。
- 草稿写入失败时保留内存内容并显示重试及导出入口；损坏草稿保持原文，不以空草稿覆盖。存储失败期间应停止扫描并先处理异常，不能保证尚未落盘的内容在断电后恢复。
- 商品资料界面及扫码绑定/新建会阻止新增重复条码。旧数据中已有的重复条码不自动合并，扫描时要求明确选择本次商品。
- 保留原有手动开单、历史单据、商品 ID、备份格式和应用标识。版本号更新 package.json、npm 锁文件、侧栏和关于页；打包核验脚本从 package.json 读取安装包版本。

## 验收

`npm test` 运行原有及新增逻辑测试；`npm run test:scanner` 在独立临时数据目录启动实际 Electron 窗口，通过键盘输入事件测试首次开单、连续扫码、真实 60 秒超时、覆盖确认、暂存归属、缺价/新商品处理、F9 前缀、页面重载恢复、最小窗口及手动开单兼容。截图和报告位于 `.shots/scanner-v2/`。

还需用店内扫码枪和真实商品完成设备验收；自动化键盘输入测试不等于实体设备验收。
