# P1 修复与数据、图片换机备份

日期：2026-11-12。范围：当前 Electron 桌面项目；未同步 Android 项目，未生成新的安装包。

## 使用方法

1. 旧电脑打开“设置 → 数据管理 → 备份到文件”，选择保存位置。
2. 把导出的完整 `.zip` 文件复制到新电脑。包内为 `data.json` 和 `images/` 图片原文件。
3. 新电脑安装相同或兼容版本，打开“设置 → 从备份恢复”，确认覆盖后选择该 ZIP。
4. 恢复完成后，客户、单据、商品、图片、公司设置、一客一价和单号序号可继续使用。

导入是整份业务数据恢复，会替换新电脑现有的业务数据。恢复前会先检查文件类型、必要集合、记录格式、金额、重复标识以及初始化商品目录兼容性；校验失败不会开始覆盖。

## 新备份包含什么

| 数据 | 处理方式 |
|---|---|
| 自建商品及导入商品 | 完整保存，含规格、单位、条码、售价、成本、备注和状态 |
| 初始化商品 | 不重复保存定义；保存关联 ID 和相对内置目录的改价、改名、下架等差异，导入时重建 |
| 已删除的初始化商品 | 不会因换机或重新打开而重新补回 |
| 客户、单据及明细 | 保存原始业务记录、备注、金额、客户快照及引用关系 |
| 一客一价、单号序号 | 保留商品/客户关联和序号，避免换机后丢价格或重复编号 |
| 公司资料、默认备注、账单标题等 | 保存并恢复 |
| 自选商品图片 | 原文件写入 ZIP 的 `images/`，不缩小、不重新编码；导入后写入新电脑的图片目录并更新关联 |
| 内置商品图片 | 继续使用应用自带资源，不重复打包 |
| 旧电脑图片目录设置 | 新备份清空该机器路径，恢复后使用新电脑默认目录 |

包内 JSON 格式为 `app: songhuodan`、`version: 2`、`kind: portable`、`archive.version: 1`。`data.products` 仅含非初始化商品；`catalog.entries` 仅用于初始化商品的身份关联及变更恢复。图片在 JSON 中用包内相对关联标识记录，图片内容以独立文件保存；导入时解析为新电脑实际路径。旧商品没有来源标记时，按条码或兼容的名称/规格/单位识别；此后新增、导入商品明确标记为自建，减少误分类。

相同图片按 SHA-256 内容去重。恢复时检查 ZIP 校验和、图片内容哈希及文件名；不使用备份中的任意路径解压。新图片先放入本次恢复的独立目录，业务恢复失败时清理该目录，已有图片不删除。备份包先完整写入临时文件再替换目标，避免写入失败破坏同名旧备份。

也可以解压后选择 `data.json` 导入，但需要保留同级 `images/`。旧版内嵌图片 JSON 会将图片恢复为本地原始字节文件；普通路径字符串不会冒充图片内容。

旧版完整手动 JSON 和原始 `sd_v1_*` 键形式的自动快照仍支持导入。旧文件的外部图片路径不会自动变成图片内容，旧图片需要另外迁移。原始抢救文件 `songhuodan-recovery` 保留损坏原文，不能冒充正常换机备份。

## 已修复的三项 P1

### R01：恢复错误结构导致清空数据

- 明确识别 version 2 换机文件、旧版完整手动备份和原始键快照。
- 原始键快照先解码、再验证，不再将其误当成缺少业务字段的空备份。
- 拒绝未知结构、混合结构、缺少客户/商品/单据集合、业务字段为 null、损坏 JSON、重复记录及不兼容目录。
- 恢复中遇到可回滚的写入失败，业务缓存、已写入键和初始化标记回到恢复前状态。

### R02：备份失败仍提示成功

- 主进程和存储 flush 接口返回真实成功或失败状态。
- 写入和图片备份失败时保留待重试标记，启动备份失败也保留该状态。
- “立即备份”强制执行，不因本轮没有业务修改而跳过。
- 图片复制或目录读取出错会传递失败；导出换机备份包时图片原文件不可读则明确中止，不生成缺图备份。
- 保存取消不报告导出成功，重复点击导出按钮也不会并发生成多个任务。

### R03：数据损坏后仍导出零金额/不完整报表

- Store 报表 API 与全部业务导出、账单、图片、分享、打印入口增加完整性检查。
- 原生打印菜单也正确消费“已拦截”的状态，防止回退到默认系统打印。
- 数据异常时仍允许导出原始抢救 JSON、导入有效备份，恢复后解除保护。

P1 和图片包修复阶段的 63 项测试全部通过；后续 P2 修复后扩展至 76 项，并补充导出专项 UI 验证，见 [P2 修复与验收](p2-fixes-2026-11-12.md)。换机、原生文件/打印、桌面及审查流程回归通过。

迁移测试使用 800×600 原图，导出后删除旧电脑原图，在另一个独立 Electron 进程中导入 ZIP，检查图片在新目录存在、字节哈希与原文件相同、显示正常且重新打开后保留，并验证能够再次备份。另验证图片缺失会中止导出，恢复数据校验失败会清理本次暂存图片，备份目录写入失败会提示失败且修复目录后可重试。

同时更新了旧回归脚本对存储后端、关闭提示及初始化目录重载行为的断言：磁盘持久化改为检查真实 JSON 文件，数据损坏注入改用文件存储桥。未修改对应的关闭或初始化业务规则。

所有验证使用独立临时目录，不恢复或清空日常业务数据，不向物理打印机出纸。其余 P2 项已在后续修复阶段处理，具体记录见上方链接。
