# 开单重复商品合并

日期：2026-11-12。范围：Electron 开单页面，保留已有 P1/P2 和 ZIP 图片备份修复。未更新 Android 项目，未重新生成安装包。

## 业务规则

- 再次添加相同商品，且规格、单位、数值单价、备注相同，数量累加到已有卡片。
- 已选商品 ID 为准，不以相同名称或图片代替商品身份。相同 ID 的商品改名后，合并仍保留已有明细的名称快照。
- 手输资料只能唯一对应一个商品时，才关联该商品 ID。商品库无对应条目时，完全相同的待建商品可以先在草稿中合并，保存整单时才创建商品。
- 若有多个同名、同规格、同单位商品，手输项保持独立；保存时提示从商品库选定具体商品，不会随意绑定到其中一条。
- 同规格不同单位、不同单价、不同备注都保留独立明细。
- 数量先做十进制累加，再按“合并数量 × 单价”的现有规则取整到分。示例：232 瓶 + 22 瓶，单价 2 元，成为 254 瓶、508 元；两次各 1 件、单价 0.125 元，合并后 2 件、0.25 元。
- 无法无损表示合并数量、数量非有限值或金额超过安全范围时，保留已有草稿，停留在货品窗口并提示调整。
- 重复确认同一个货品窗口只执行一次。

编辑卡片数量是替换，不把输入值再次累加。例如当前数量 6，编辑为 7，结果为 7。已有历史单据打开时不自动改写；明确添加新项时，会在草稿中合并所有与新项兼容的重复行。保存前，已存单据保持原值。复制新增也不改变源单据。

同一商品存在多种价格时，保存“一客一价”采用当前单据中最后确认且仍存在的商品行；已删除的行不参与。未确认过货品行的旧单据编辑，仍沿用原来的明细顺序决定价格。

## 性能处理

- 合并只检查当前单据，不扫描历史订单，不在后台定时整理数据。
- 已选 ID 的普通匹配无需额外查询商品库；手输商品需要时进行一次只读识别。
- 正常追加只插入一张卡片；单行匹配仅更新金额、数量文字，其他卡片及图片节点保持不变。
- 给手输项补充商品 ID 时，仅重建该卡片；多条旧重复行合并、编辑或删除时，沿用明细区域重绘以确保索引正确。
- 添加和合并不创建商品、更新客户价格或写入订单；这些动作在保存整单的事务中完成。

本机真实 Electron 的 300 行草稿测试，单次合并处理约 1 毫秒，所有原卡片节点保留，历史查询、商品查询、商品创建和业务事务调用次数均为 0，业务 revision 未改变。耗时为同步确认处理测量，不包括输入对话框、下一帧绘制或保存整单，不作为所有机器的性能保证。
