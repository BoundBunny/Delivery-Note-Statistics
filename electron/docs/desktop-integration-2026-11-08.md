# Electron 场景工作台接入记录

> 历史记录：独立项目迁移后的结构与验证结论见 `docs/standalone-2026-11-09.md`。以下路径和测试数字为当时状态。

## 已接入正式应用

正式 Electron 首页采用已确认的「DNS · 送货现场」视觉方案，原生 3D 仓库铺满工作区，经营数据、业务速览和最近单据以浮层展示。

数据来自原有 `Store`，没有将设计示例单据、客户或单价写入应用。原 `index.html` 的加载地址、应用标识、用户数据目录和 `sd_v1_*` 业务键保持不变，已有数据不迁移、不清空。

## 主要实现

- `preload.js` 仅向 Electron 提供桌面能力标识与本地资源地址。共享入口根据该标识加载正式桌面控制器，Android/普通浏览器继续使用原界面。
- `renderer/desktop.js` 从 Store 读取单据、商品、客户和设置，计算当前本地日期与月份的指标，处理搜索、资料速览和导航。
- 开单、编辑、客户/商品管理、统计、打印和备份仍使用现有 `Views` 与原生桥。保存后选中刚查看/保存的单据，返回首页刷新真实数据。
- 保留原 `#view-container`，不同时运行两套路由，避免重复分配单号或丢失草稿。客户字母索引已补偿固定桌面顶栏高度。
- 桌面视觉样式通过 `@scope (#desktop-app)` 隔离，业务表单与打印布局不受外壳样式覆盖。打印时隐藏场景、导航与提示消息。
- 商品/客户速览支持直达真实编辑表单；账单速览与 Excel 导出调用现有月度分组、标题与导出函数。
- 场景按需加载、复用同一实例；进入业务页或隐藏窗口时暂停。尊重减少动态效果偏好，桌面偏好使用独立键 `sd_desktop_ui`。
- 窗口保留历史尺寸，新用户默认尺寸根据屏幕工作区限制到 1440×960；最小窗口仍为 1024×680。
- `Ctrl/Cmd+P` 对已保存单据打开打印预览，在打印/账单页调用原生打印；不打印未保存的草稿。
- `scripts/build-desktop-assets.cjs` 只生成视觉外壳、隔离样式和共享场景，不将示例控制器打包。开发启动及安装包构建前会自动执行。

## 回归检查

- 18 项正式 Electron 集成检查通过，使用真实 `main.js`、preload 和原页面入口，覆盖真实数据、空状态、跨月汇总、保存/重载、复制、打印、原生编辑表单、客户字母索引、搜索、备份恢复、偏好、小窗口、大额数值、日夜灯光和离线请求。
- 12 项数据层测试、9 项共享业务 UI 场景、12 项原沙盘专项测试通过。
- 原生打印生成一页 PDF，提取确认包含正确客户、单号与金额，不含工作台界面和“已保存”等提示消息。
- 所有检查使用独立临时 profile，未读取或覆盖日常业务数据。

截图、PDF 与检查记录位于 `.shots/electron-live/`。Windows 安装包位于 `dist/`，运行目录位于 `dist/win-unpacked/`。安装包未配置商业代码签名。

## 安装包验证限制

`scripts/verify-desktop-package.cjs` 对包内 37 个源码/视觉/共享资源逐字节核验，确认未打入原型示例控制器；使用项目现有 Electron 运行时执行实际 `app.asar`，10 项启动自检通过。

当前自动化执行账户直接启动打包 EXE 会遇到权限/沙箱限制，无法创建临时缓存目录，因此 **EXE 直接启动未标记为通过**。未为绕过该限制关闭正式程序的沙箱，也未更改系统安全策略。安装包需在正常 Windows 桌面会话中双击确认启动。

## 边界

本轮优化针对 Electron；没有重新构建或替换 Android APK。独立的设计原型继续可用，但其示例数据与正式应用完全分离。JSON 备份仍不打包本地商品图片，图片目录需单独备份。
